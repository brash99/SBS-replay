Hi Ben,

Okay, I am attaching a bunch of plots to this message, but you can find them also in my GitHub repo under the scripts directory at ~/lh2plots_6077.  They are for run 6077.

I calibrated the time offsets and the CDet-Ecal timing factors using run 3575 (cross target).  The offsets are stored in the file called CDet_bar_toffsets.dat, but also I made a copy called CDet_bar_toffsets.dat.3575 for comparison and so that they are not lost 🙂
The CDet-Ecal timing fit parameters are:  

gECalFitP0 = -40.303
gECalFitP1 = 0.63615

And are found in PlotElastic_with_barhits_offsets_io_ecalcorr_apply.C at line 248.

Using this, I then ran one segment of one stream for run 6077 (LH2) - about 30000 events total.  The specific command was:

 .x PlotElastic_with_barhist_offsets_io_ecalfit.C(6077,-1,0,0,5,20,35,8,40)

So, as you can see, that is using a LE time window of 20-35 ns, so focusing on that “peak” that might be the good electrons.  Also, a TOT window of 8-40ns.  These cuts are probably too narrow for our eventual production cuts, but the point here is that I wanted to see if we could cleanly identify good electrons coincident with ECal for an LH2 target.  We can back off the cuts a bit later, for hit selection to send to the overall tracking routines with other detectors, but, of course, we want to be very sure that we are identifying the good primary electron!  So, this is a proof of principle.

Also, the XDiffCut (with ECal) is the default +/- 2 cm.  So, yes, pretty narrow, but again it’s about cleanly identifying the good electron here.

You can see the resulting LE, TE, and TOT plots in All TDC.pdf attached.  Because of the CDet-ECal calibration that has been applied, the “peak” occurs around 30ns (because it has been calibrated to show up there).
I then ran the following command:

 plotCDetLayersTimeComp(1,-15,15,-0.1,0.1,20,35,8,40,-15,15,0,60,0,80,95,125,-104,-60)

Which of course creates all of the other plots.  Again, note the LE timing window is 20-35 ns.  Now, if you look at the mean value of the LE plot in Step 4, you will see the actual mean is 28 ns, so this means we are taking and ~+/- 8ns window around that.  I know that I probably should have adjusted this to be exact, but I was not thinking carefully at the time, and did not feel like regenerating all the plots this morning!  Then again, looking at the CDet Layer 1/2 Good Time 1D plots (see next step), the peak seems pretty centered in that window, to my eye, so maybe it’s okay.

You will notice that the ECal time cut is 95-125 ns, which again limits things to only “good” ECal times, and hence when one looks at the profile plot of CDet time vs. Ecal time, one sees that!   

From my point of view, all of the other plots look pretty good, and so I think that this exercise was successful.  The main point I would like to emphasize is that all of the calibrations were done with run 3575, and then applied to run 6077.  So, I feel like that is a nice confirmation that things did not change massively over a pretty long time window of the experiment.
